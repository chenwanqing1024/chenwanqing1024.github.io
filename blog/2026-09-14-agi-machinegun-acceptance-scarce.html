AGI 机关枪发下来了，可谁来验收

2026-09-14 · AI Agent 读文笔记 工程判断

读文笔记。本文是对他人文章的摘要与评述，非原文转载。 原文：AGI 机关枪发下来了 · 冯若航

原文在说什么

冯若航写了一个对照：蒋老板一个月用 Codex 烧出四个数据库、一套操作系统、一门编程语言、一个编译器和一颗 CPU，架构方向（主数据 S3、元数据 PG）甚至被老冯自己认可；老冯自己则接盘 MinIO 做 Silo——自己懂对象存储、Agent 负责搬砖。从这两个一冷一热的对照，他推出全文最锋利的判断：AI 真正有价值的地方，是让已经拥有专业判断的人，不必再亲自完成所有体力劳动——不是让门外汉凭空拥有专业判断。

他接着推出”供给无限”的论断：许愿就能得到软件的时代到了，门槛降了几个数量级。但紧跟一盆冷水——AI 容易把项目从 0 推到 80 分，真正困难的是把剩下 20 分补完：兼容性、边界条件、安全、迁移、升级、回滚、可观测性、长期维护、出事谁负责。这最后 20 分，可能吃掉 99% 的成本。 稀缺的不是代码，是”正确的愿望”和”验收能力”。代码无限，信任从来不无限。

接下来他解释为什么是”这一个月”——Fable 5 恢复全球访问、GPT-5.6 普遍可用，跨过了”能不能独立完成长时间大型工作”这条线。然后用杰文斯悖论解释订阅为什么从两个涨到10 个还会涨到 20 个：能力涨，需求不是线性涨，而是爆炸涨。

最后老冯用 Tibo 48.5 万关注者做”圈层温度计”，推出关键判断：真正稀缺的不是 AI 工具，而是认知差——10 亿人触达 OpenAI，只有约 1500 万真正用 Agent 干活，深度用户再除几个数量级。以后稀缺的是洞察力（发现真问题）、影响力（推到用户面前），加验收能力作为入场资格。

我的看法

我认同的部分：80/20 法则和”信任从来不无限”是最锋利的判断

整篇文章读下来，最让我点头的不是”机关枪发下来了”那种修辞，而是中间那一段——“AI 容易把项目从零推到 80 分，真正困难的是把剩下 20 分补完”。这一刀切得准。 我自己做后端工程这些年，见过太多”能跑”的代码卡死在第 20 分上：RocksDB 状态后端参数不调对、Flink Checkpoint 失败时状态回滚路径没设计、并发场景下锁竞争要 jstack 才能看见。这些活的特点是上下文极大、需要工程直觉，AI 给的多半是教科书答案——它能写出 RocksDB 的示例配置，但看不出你的写入模式是写多读少还是范围扫描为主，所以调参方向会跑偏。

“代码无限，信任从来不无限”这句话老冯写在文末做收束，其实才是全文的真正重量。它把”AI 时代稀缺什么”这个问题从”技术能力”挪到了”关系和责任”层面——前者是工程问题，后者是组织问题。一个没人在乎的玩具 GitHub 上多到溢出，能让人把业务、饭碗、数据交出来的产品从来都不多。

我的 push back 之一：蒋老板其实是”有品味的门外汉”，不是真门外汉

老冯的叙事有一个内在张力。他在 Silo 段写得清清楚楚：“老冯对 MinIO 有些了解，并非两眼一抹黑地在聊天框里敲一句’帮我维护一下对象存储’。”——必须懂，才能验收。但蒋老板段他又写：“蒋老板本人应该并不熟悉 Rust”，照样烧出了 graphdb / RustDB / rutomq / microsystem，还能上生产。

这两个立场在文章里没有和解，但其实是同一个事实的两面。 蒋老板不是”不懂数据库”的门外汉，他懂的是另一层——他知道”主数据放 S3、元数据放 PostgreSQL”是数据服务未来的大方向，这个判断本身就是十几年架构师才能攒出来的。他用 Codex 写代码，但他用的是老冯认可的方向写代码。他缺的是 Rust 语法，他不缺的是品味。

老冯用”AGI 机关枪”这个比喻把”门外汉也能产出来”浪漫化了，但蒋老板的成功是因为他其实不门外——他是用他的 selection（知道什么值得做）换了 Agent 的 execution（把代码烧出来）。真正稀缺的从来不是会写代码的人，是知道什么代码值得写的人。 老冯在文末也承认了这点（“第一是洞察力”），但叙事重心却落在”机关枪门槛降低”上，这就把他的真正洞察藏在了副线里。

我的 push back 之二：“绝大多数人还没进场”是 selection bias

老冯用 Tibo 48.5 万关注者证明”早期窗口”。但 Tibo 是 OpenAI 内部 Codex 高频用户样本，关注他的人本身就是 AI 重度用户群里更活跃的那一小撮。用这个数推”10 亿人触达 vs 1500 万 Agent 用户”是对的，但用这个数推”早期窗口”会高估——真正的”绝大多数人”是 80 亿减 1500 万，差距比”早期窗口”这四个字暗示的要大。

真正有意思的不是”早期窗口”，是”早期窗口里的层级”。 这 1500 万里，能稳定打满一个最高档订阅的除掉好几倍；能同时跑多个 Agent 做并行项目的再除掉好几倍；能把多个 Agent 的产出组织起来形成产品、且有人用、能产生真实影响的，再除掉好几倍。这个漏斗不是线性的，是对数级的。OPC 之所以让人羡慕，是因为它站在漏斗的最后几档，并且把上层的浪费成本自己消化了——订阅费是小的，回滚、兼容性、出事担责才是大头，全落在他一个人头上。

我加的例子：Agent 给的是教科书答案，工程师直觉介入才有方向

从我的领域（Flink / Paimon / JVM 后端）出发看”AI 提效”是不均匀的。写 CRUD、写 ETL job 模板、生成单元测试脚手架——AI 写得比我快也比我齐整，这块已经被吃掉了。但往深处走几步就不一样：Flink 的 Checkpoint 失败回滚路径、RocksDB 状态后端的参数调优、读 Paimon 源码理解 LSM 树 compaction 触发条件——这些活的特点是上下文极大、需要工程直觉。

AI 能写出 RocksDB 的示例配置，但它看不出你的写入模式是写多读少还是范围扫描为主。它能解释一遍 synchronized 和 ReentrantLock 的语义差别，但它看不出你线上 GC 日志里 CMS 退化标记和 Full GC 的因果链。这不是”AI 不能做”，是 AI 在没有工程师直觉介入时做不好。 老冯自己在 Silo 上处理十余项安全问题（含认证绕过高危漏洞）的案例正是这个模式的现实样本——Agent 写补丁、人做架构判断和回归验收。

这条路比”烧十把机关枪”慢，但它对 ladder 第一格的人是可执行的。在 AI 已经啃动的红海里拼烧代码的速度是送人头；在 AI 还啃不动的深度工程里，把”知道什么值得做”和”知道烧出来的东西哪里可能有问题”叠在一起，是给 average 工程师留的真正窗口。

一句话总结

老冯把”AGI 机关枪”叙事推到极致，但最锋利的不是”门外汉也能烧”，而是”代码无限、信任不无限”和 80/20 法则——稀缺的是 selection（知道什么值得做）和 acceptance（知道哪里可能有问题），不是 execution；蒋老板的”门外汉”其实是”有品味的门外汉”，这条路对 ladder 第一格的人不可复制。

蹬掉 10 个订阅不难，难的是把自己 scale 起来

2026-09-14 · AI Codex Agent 自动化 复利 读文笔记

读文笔记。本文是对他人文章的摘要与评述，非原文转载。 原文：如何蹬掉 10 个 200 美元的 Codex 订阅？ · 冯若航

原文在说什么

冯若航这篇文章其实只在表层谈”如何凑齐 10 个 AI 订阅”，真正想说的是另一件事：订阅从来不是瓶颈，能把订阅”蹬完”才是。

他把论证拆成三步。第一步是”买得到”：邮箱、企业域名、外卡、Chrome Profile、本地机器，凑齐六样就能开十个。这一段写得坦率且操作化——手机号可以走一次性短信验证平台，外卡用 Airwallex 走公司主体，Chrome Profile 一个挂两个 ChatGPT 加一个 Claude，本地五台机器加五台云电脑各挂一个账号。第二步是”蹬得完”：他自报每天消耗约 4 个周配额，一周 ≈ 28 个 200 刀订阅的量，三个月烧掉 3000~4000 亿 Token，配上 Tibo Reset 和重置卡勉强跟得上消耗速度。他的判断是订阅费跟招人比简直便宜得不像话，“我不觉得有哪家企业连这点钱都掏不出来”。但真正的瓶颈在转化效率——很多公司眼下的尴尬是只能量化 Token 消耗量，于是把 Token 消耗量当成考核指标，最后只能拿到 Token 消耗量本身，古德哈特定律。第三步是”把自己 scale 起来”：核心做法是持续自动化、做有复利的事，搭出能自己运转的体系，让 AI 成为放大时间、注意力和验收能力的指数级工具。

我的看法

认同的部分：Token 不是瓶颈，转化效率才是

“订阅费不是瓶颈，转化效率才是”——这句话就是当下大多数企业 AI 转型的真问题。我自己在做 Agent 工程和 RAG 的过程中见过太多团队，第一反应是算账、买账号、配额度，第二反应是盯着 Token 消耗量做报表。结果呢？额度是发出去了，但真正交付到生产里的自动化能力少得可怜。冯若航那句”规定每人每天必须烧掉一亿 Token，那大家就一定能烧掉一亿 Token”——这话刺得准。古德哈特定律在 AI 时代的企业里不是隐性风险，是显性事故。

更让我认同的是他对”复利”的强调：做有复利的事，前期必须做大量不 scale 的事。这不是鸡汤，是工程经验。他自己举的 PG 扩展例子很具体——积累几百个可用样例后，更新一个扩展版本只需要一句话，后面甚至定时任务自动扫 PGXN/GitHub/Google 找新版本、自己触发构建。这种 pipeline 不是天掉下来，是堆手工活堆出来的。我自己前几年做数据湖仓的时候也走过同一条路：先把每个组件的运维脚本手写一遍、把所有出错的边界情况记下来，再回头抽象成 SOP，最后才能让 Agent 一句话接管。没有前面两年手抄的复利基础，后面那句”按 SOP 处理一下”是说不出口的。

限定与边界：个体户玩得通，组织里玩不通

冯若航整篇文章默认的前提是”个体户玩家”。但有两件事我想限定一下。

第一，“蹬得完”这个问题的答案，在个体户和在公司里完全是两回事。个体户可以靠灰色操作（重置卡、虚拟号、多账号），企业里这一套直接踩合规红线。企业能做的只有”按人头给订阅、把 Token 配额开放、把自动化权限给到工程团队”——这意味着企业真正的瓶颈不是订阅费，是组织里”敢不敢让 AI 替你做决定”的权限结构。这件事大多数公司到现在都没想清楚，于是 AI 永远停在”代码补全 + 文档总结”那一层，跨不进真正的流程自动化。

第二，“细节验收可以彻底交出去，自己只做宏观验收就行”——这个方向我接受，程度我不接受。当下 Agent 工程的实际体验是：宏观验收容易（架构对不对、流程有没有闭环），微观验收也容易（单条 SQL 跑没跑通、单个 API 通不通），最难的是过程验收——AI 在多步推理里中途偏掉了，但每一步看起来都”通”，最后整体逻辑错位。这种错位当下非常常见，而且不是”模型变强了就没了”，而是必须靠工程手段主动防御。每一步要留什么中间态、怎么回溯、怎么人工打断，这是当下 Agent 团队最花时间的事——也是冯若航那句”细节验收交给 AI”覆盖不到的灰色地带。

加的例子：把”一句话让 AI 干活”做成产品

我自己做 Agent 的时候有一条原则跟冯若航的”复利”对齐：每个 Agent 必须留下三个东西——可执行的 SOP、可追溯的中间态、可复用的样例库。SOP 是把”一句话让 AI 干活”翻译成确定步骤；中间态是过程验收的基础；样例库是复利的载体——你做了一次的事，AI 下次能直接调用。这三条一旦立起来，单 Agent 的边际成本才会真的趋近于零。缺任何一条，要么每次都要重新解释（高边际成本），要么 AI 跑偏了你没法回溯（高返工成本）。

还有一点冯若航没展开但很重要：他把 Astra 6 重扫 SILO 这种”用新模型回头修旧代码”的工作流写得很轻，但这是企业最容易漏掉的部分。代码不是一次写完就完了，每次新模型出来都要回炉重造一遍。这件事在企业里如果排不进 roadmap，就只能靠个人私下用订阅撑。组织的 AI 能力和个体的 AI 能力，差距会越拉越大。等到员工离职的时候你才发现：他个人靠 10 个订阅撑起来的复利体系，组织里谁也接不住。

一句话总结

订阅费从来不是瓶颈，能持续堆出可被 AI 自动化的手工活、搭出能自己运转的复利体系、把验收范式从细节转向宏观——这才是当下真正的稀缺资源。
